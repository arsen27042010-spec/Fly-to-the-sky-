# 02 — Architecture

Built on **Branch v2.5.2** ([reference](../reference/Branch_API_Reference.md)) with the default `"Suffix"` segment rule: modules ending in `Service` (server) or `Controller` (client) are segments; anything else is a helper.

## Server segments

| Service | Depends on | Owns |
|---|---|---|
| PlayerService | — | `Data.Start` (template in [04](04-data-progression.md)), leaderstats, character parking during runs |
| ModeService | PlayerService | Server mode (`Normal`/`Pro` from `game.PlaceId`), PRO level gate on join, teleports ([08](08-pro-servers.md)) |
| ZoneService | ModeService | Zones and sites registry; assigns numeric `Id` attributes to guards and targets (sorted by full name, so server and clients agree); moves PRO zones in on PRO servers |
| RocketService | PlayerService, ModeService, ZoneService | Runs: launch, `RunConfig`, state stream validation, snapshots to others, server-side fuel, hit tests, explosions, run end |
| GuardService | RocketService, ZoneService | Guard AI, vision, suspicion per rocket, firing, guard snapshots |
| TargetService | RocketService, ZoneService | Target HP, regen, damage shares, respawn, reward payout |
| ProgressionService | PlayerService | XP, levels, level-up events, unlock checks |
| ShopService | PlayerService, ProgressionService | Upgrades, skins, rebirth |

## Client segments

| Controller | Owns |
|---|---|
| InputController | `Branch.Keybinds` contexts `Lobby` and `Flight`; exposes aim deltas, throttle, detonate |
| RocketController | The local rocket: fixed-step simulation, collisions, state machine, sending state, applying corrections |
| RocketReplicationController | Other players' rockets: snapshot buffer, Hermite interpolation, LOD |
| CameraController | Hub camera, chase camera, standing orbit, kill cam |
| GuardController | Turret rotation from snapshots, vision cone visuals, alert icons and sounds |
| EffectsController | Flame, trail, ignition, jet wash, scorch marks, explosions, dust, all pooled |
| HudController | Cash, XP bar, suspicion meter, fuel bar (PRO), notifications, LAUNCH button |
| ShopController | Upgrade, skin and rebirth UI |

## How segments talk

- **Server ↔ server:** direct method calls on segments fetched with `Branch:GetSegment` in `Init`/`Start`. Annotate return types of methods other segments use.
- **Server ↔ client:** only Branch compiled networking ([03](03-network.md)).
- **Persistent state:** `Branch.Data.Server` on the server; clients read their own mirror through `Branch.Data.Client.Observe`. No extra "data changed" events.
- **Field ownership:** each data field has exactly one writing service ([04](04-data-progression.md#field-ownership)).

## RunConfig

Built by `RocketService` at launch and read by every other service through `RocketService:GetRun(player)`:
```
RunConfig = {
    runId, zoneId,
    mode,            -- "Normal" | "Pro" (the server mode)
    fuelEnabled,     -- mode == "Pro"
    rewardMul,       -- 1 or 2
    xpMul,           -- 1 or 1.5
    suspicionMul,    -- 1 or 1.5
    timeout,         -- 180 s Normal, 120 s Pro
}
```
Nothing else in the code branches on the mode directly: new modifiers go into `RunConfig`.

## Run lifecycle

1. The client presses LAUNCH → `RocketService.Launch(zoneId)`.
2. The server checks: data loaded, no active run, zone unlocked, cooldown. It builds `RunConfig`, parks the character (HumanoidRootPart anchored in the hub), sends `RunStarted` and `RocketAdded` to everyone.
3. The client hides character controls (`PlayerModule:GetControls():Disable()`), switches the camera to chase mode and spawns its rocket standing on the launch pad.
4. Flight: the client simulates and sends `State` at 30 Hz. The server validates, keeps the last valid state, sends batched `Snapshot`s at 20 Hz, runs hit tests, and receives suspicion from `GuardService`.
5. End: detonation, crash, spotted, timeout, out of bounds or rejection → the server resolves damage and rewards, then sends `RunEnded`, then `RocketRemoved`.
6. The client plays the kill cam, restores the character and the hub camera.

## Streaming

The rocket is client-only while the character stays parked in the hub. With `StreamingEnabled`, distant zone geometry could be missing on the client, and the rocket would fly through it.
- **Zone 1:** turn `StreamingEnabled` off. The simplest option; zone 1 is small enough.
- **Later, when the map grows:** keep streaming and give each player a server-side invisible anchored focus part that follows the validated rocket position, set as `player.ReplicationFocus` during runs.

## Collision rules

- Spherecasts and raycasts hit parts with `CanQuery = true`, regardless of `CanCollide`. So everything solid has `CanQuery = true`, and decor the rocket should pass through has `CanQuery = false`.
- Rocket parts and every effect part: `CanQuery = false`, `CanCollide = false`, `CanTouch = false`.
- Server rays (wall checks, guard line of sight) use an include filter on `Workspace.Zones.*.Geometry`.
